# Accessibility checklist

- [x] All four tabs have concise accessibility labels and stable UI-test identifiers. Verified in the simulator UI hierarchy.
- [x] Bus stop annotations expose stop code and name without requiring map vision. Verified in source and the simulator UI hierarchy.
- [x] Reported-bus annotations expose the arrival order and full countdown to VoiceOver while their visual marker shows the compact minute value. Verified in source and the simulator UI hierarchy.
- [x] Compact ETA cells combine service, minutes, monitored/scheduled state, occupancy, bus type, and wheelchair status into one accessibility label. The visual crowd glyph was removed, but VoiceOver still names the exact LTA occupancy; the service disclosure announces direction. Automated UI assertions cover single deck, double deck, accessible, and not-accessible mock arrivals.
- [x] Stale state has a textual label. Occupancy is visually colour-coded as requested and is also exposed verbatim in each ETA's VoiceOver label.
- [x] Dynamic Type remains usable at accessibility extra-extra-extra-large. The simulator launch argument exercises the fully scrollable layout, scaled service tile, primary service/favourite actions, selected-route map, and return control; the automated flow passes.
- [x] Stop browsing uses native lazy scrolling with pinned section headers; tapping the stop identity focuses or collapses that same section while retaining the surrounding hierarchy and all earlier stops. Refresh and favourite actions exist only in the focused header; favourite renaming remains available from the native Favourites context menu. Service management uses a native Menu whose full-route action opens a standard dismissible sheet. A route row announces whether it will show bus locations or return to the stop map; the selected map states how many of the next three locations LTA reported. The full route sheet labels its map, geometry status, direction, stop count, and each ordered stop for VoiceOver. The optional identity font is controlled with a native Toggle.
- [x] Location and reported-bus-location controls use explicit 44-point-or-larger targets; other controls use native button and tab sizing. Source-audited.
- [x] The arrival board uses no continuous ambient animation. SwiftUI animates bounded focus/collapse positioning, which becomes immediate under Reduce Motion. Persistent MapKit camera transitions also become immediate when Reduce Motion is enabled. Settings exposes the actual system state.
- [x] Map, search, and favourites remain usable without granting location permission. Automated mock UI tests launch without requesting permission and cover all three areas. Pinned Favourites ETAs retain the same per-estimate VoiceOver summaries as the main board, and the stop header remains a separate canonical-map action.
- [x] Tiny overview and medium-dot visuals retain practical annotation/button hit regions; close signs expose stop code and name. The route map uses at least 44-point targets at every visual level. The interchange bus symbol is supplemental—the stop remains identified by its code and name rather than icon alone.
- [x] Empty, stale, error, and not-in-operation messages use explicit text and recovery guidance. Source-audited.
- [x] Dark and light appearances preserve readable contrast in the tested Map and arrival-board states. The automated dark pass uses the app's real Appearance picker.
- [x] Pre-arrival assistance exposes a centre Assistant tab that opens directly to a 116-point labelled voice control and can be the default launch screen. It accepts spoken boarding stop/current location, service, and assistance; provides an English transcript; exposes explicit listening, processing, sending, sent, received, failed, and cancelled text; and keeps **Confirm & Send** above the floating tab bar after interpretation. Passenger-readable fields, non-colour status symbols, contextual/manual recovery, VoiceOver acknowledgement, speech, and haptics remain available. Automated unit/UI coverage verifies global and selected-journey voice paths, the manual path, structured journey resolution, premature-ACK guard, and acknowledgement-owned state transition; retained global-request and acknowledgement screenshots were visually inspected.

Checked items state their evidence. Broader screen-by-screen VoiceOver testing remains part of release QA.
