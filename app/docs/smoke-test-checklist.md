# Smoke-test checklist

- [x] Cold launch in deterministic mock mode reaches Map with a selected nearby stop and arrivals already visible, without a preliminary tap. Automated UI test.
- [x] Undetermined location falls back to Singapore without blocking the map. Automated UI tests suppress the permission request and still select a map stop.
- [x] A visible map stop replaces the persistent arrival board in place without presenting a sheet. Automated UI test for stop `01012` also asserts that no sheet exists.
- [x] The lower Map surface remains one native lazy vertical scroll surface in both states, with one stable pinned `Section` header per stop. **Nearby stops** collapses its focused section to stop-only rows: no route row, ETA, refresh, or favourite control remains. Choosing stop `01012` focuses that same section, merges freshness/refresh/favourite into its identity header, anchors freshness at the top-right, and issues one smooth upper-position request. Exact top alignment is used when real content permits it; a short list does not create an artificial tail to force it. Arrival updates do not repeat the animation, scrolling upward reveals earlier stops without triggering refresh, and the final stop is the real lower scroll bound with no extra blank viewport. Automated UI frame/scroll-bound tests and retained simulator screenshots.
- [x] Repeated nearby-stop changes never leave a blank or stale board, overlap two branches, animate rows through one another, reorder around the selected stop, or navigate away from the stop hierarchy. Automated UI tests switch `01013` → `04167` → `01012`, sample adjacent row frames throughout branch changes, verify bounded upper focus positioning, and verify a stop-specific arrival after every change.
- [x] The Map tab has no app-title/navigation bar; its persistent map reaches the top screen edge behind the status bar, while map controls remain below the safe-area inset. Automated UI frame and navigation-bar assertions plus retained simulator screenshot.
- [x] Focused refresh and favourite targets share one horizontal center line and precede the native trailing disclosure indicator. Collapsed stop labels and disclosure indicators span the full list width; the unconstrained overlay divider that previously rendered vertically is absent. Automated frame assertions and retained simulator screenshot.
- [x] Three mock arrivals render with stable slot identifiers. Automated UI test for service `7`.
- [x] Service destinations and the service-count/jump button are absent from the compact board. Services `7`, `14`, and `16` render in equal-size borderless `RGB(147, 213, 0)` tiles using the supplied LTA Identity face; retained light-mode screenshot inspected.
- [x] ETA cells have no grey container or crowd icon. ETA text uses standard SF Pro plus green/amber/red occupancy colour, metadata uses larger native live/scheduled and single-/double-deck symbols, and only a non-accessible bus shows the slashed wheelchair state. UI assertions cover the complete VoiceOver semantics, and a native-symbol availability unit test prevents silent missing glyphs.
- [x] Tapping service `7` retargets the persistent upper map to its three reported mock-bus locations while leaving the compact route list unchanged. Automated UI test and retained simulator screenshot.
- [x] The selected-route map labels each reported bus with its floored ETA (`1'`, `6'`, `13'` in the retained mock screenshot), never with `1`/`2`/`3`; reports `3 of 3 locations reported`; draws the cached stop sequence in the same map; retains the selected stop in the camera extent; and returns to the stop map by tapping the row again. Formatting unit tests and automated UI assertions cover the marker values.
- [x] Route selection, return to stops, recenter, and map-marker stop selection retain one `MKMapView` for the whole transition. Automated UI tests repeatedly assert that the persistent surface never disappears while MapKit animates the camera; marker and list selection preserve the current span, Nearby Stops requests a close `0.006` latitude span, Locate requests `0.005`, and marker selection also verifies the newly focused stop board.
- [x] Pinch zoom changes the actual native map latitude span in both directions. An automated UI test verifies that pinch-out decreases the span, pinch-in increases it again, and recenter remains functional afterward.
- [x] A partial upstream location response is represented honestly: mock service `14` shows only its two reported markers and states `2 of 3 locations reported`. Automated UI test; no third position is inferred.
- [x] No expanded arrival-detail block or segmented arrival picker appears after route selection. Automated negative UI assertions.
- [x] Pull to refresh updates the timestamp and preserves row identity. Automated UI test performs the gesture, observes a changed full last-updated value, and rechecks all three stable arrival-slot identifiers without replacing the board.
- [x] Leaving Map or deactivating the app cancels the board polling task; cancellation propagates to the in-flight provider request. The full route sheet reads cached static data and starts no arrival-polling lifecycle; dismissing it cancels its on-demand geometry task. Source-audited active-tab gating plus a dedicated cancellation unit test.
- [x] Search matches stop code, stop name, and road name. Unit coverage covers all fields; UI coverage for code and road also verifies that selection returns to the same Map List, focuses the selected row at the top, and does not open a second stop view.
- [x] Selecting a search result records it in Recent. Automated UI test selects stop `01012`, terminates and relaunches the app without resetting preferences, then verifies the labelled Recent result.
- [x] A favourite can be added, renamed, persisted, displayed under its custom name, and removed. Automated UI and persistence unit tests.
- [x] Services can be pinned and reordered, but never hidden. Pin/unpin UI coverage explicitly verifies that no hide/restore action exists; ordering persistence has a unit test.
- [x] The selected service draws only cached road-following sections in the persistent main map, never straight stop-to-stop substitutes, with no pushed route view or navigation bar. Its ellipsis menu places **Bus route** directly below pin/unpin and presents a native route sheet with an independently zoomable map, honest geometry status, all route-stop markers, and the connected LTA stop sequence. The list opens with the invoking stop slightly below the top and uses a translucent LTA-green current row with semantic dark-mode-safe foregrounds. Route markers have at least 44-point targets. Marker selection scrolls the list and recentres the map; row selection recentres the marker; **Show on map** dismisses into the canonical main view focused on that stop. The disabled alight button states that it is future work. Automated end-to-end UI coverage exercises both selection directions, marker centring, disabled reminder, canonical handoff, and light/dark screenshots.
- [x] Active services remain first. Scheduled but currently inactive services remain visible beneath them with a tested `Resumes 5:30 AM` state; overnight service-window evaluation has unit coverage.
- [x] Compact reusable stop-code annotations replace default pins. Sign, dot, and overview modes use required annotations so MapKit cannot silently suppress a real opposite-side stop. Broad overview uses tiny green dots rather than clusters; conservatively derived interchange/terminal stops use a slightly larger circled bus icon. The same three levels exist in the route sheet, with practical invisible hit targets around small visuals. Automated UI coverage asserts the opposite-side stop, all density states, absence of clusters, route interaction, and zoom transition; retained simulator screenshots were inspected.
- [x] Favourites shows three ETA cells immediately below each explicitly pinned service. It fetches one arrival board per pinned stop only while Favourites is visible and the app is active, then filters locally; leaving the tab cancels the task. Automated UI coverage pins service 7, verifies its ETA row lies below the stop header, and returns through the canonical Map focus.
- [x] Settings includes a native **Open to Favourites** preference. It persists locally, applies on the next app launch without switching the current screen, and defaults to Map for existing payloads. Unit persistence and terminate/relaunch UI coverage.
- [x] Failed road legs persist retry timing without persisting fabricated geometry. Reopening during the cooldown makes zero provider calls; manual refresh retries immediately. Dedicated disk-reopen unit coverage.
- [x] Route geometry persists by adjacent stop pair, remains fresh for 30 days, deduplicates simultaneous requests, and is limited to 40 MapKit Directions requests per rolling minute. Unit tests cover disk reuse without another request, stale/manual refresh, incompatible schema rejection, and a budget below MapKit's 50-request burst ceiling.
- [x] Static data update succeeds in mock mode and preserves the prior snapshot on failure. Dedicated data-store unit test performs a successful install followed by a failing update.
- [x] VoiceOver labels are meaningful in the inspected hierarchy; an automated accessibility extra-extra-extra-large Dynamic Type launch verifies the stop name, service row, favourite action, selected-route map, and return action remain visible and usable.
- [x] The bundled font registers as PostScript name `LTAIdentity`; Settings can disable and re-enable it through the native **LTA Identity typography** switch. Unit registration/persistence tests and an automated UI switch-state flow cover both paths.
- [x] The glance board uses no continuous ambient animation. Focus and collapse use SwiftUI's bounded disclosure/scroll animation; Reduce Motion makes list positioning and MapKit camera transitions immediate.
- [x] Light mode is legible in the arrival-board and selected-route-map states. Dark mode is covered by the automated accessibility launch and retained screenshot.
- [x] Live BusArrival v3 succeeds with the user-supplied local key. At 16:44 SGT on 23 July 2026, real stop `01012` returned 11 services with a reported next arrival for each; the live-configured simulator app subsequently rendered real monitored arrivals at stop `01619` without the Mock badge. The key file was confirmed ignored and untracked, and the built development app was confirmed to receive the same local value without printing it.
- [x] Pre-arrival assistance is reachable both from the centre Assistant tab and from a selected upcoming service without replacing the persistent map or ETA board. The global flow starts on the microphone, transcribes a stop, Bus 191, and assistance need, resolves stop `01012` through transit data, shows the constrained request, keeps **Confirm & Send** above the floating tab bar, and reaches vehicle-owned ACK. Manual and selected-journey voice still create the same validated `AssistanceRequest`. Dedicated unit tests cover global journey resolution, invalid model actions, premature ACK language, delayed acknowledgement separation, acknowledgement failure, and the Bus 191 mock arrival. Targeted global and selected-journey end-to-end tests pass on iPhone 17 Pro / iOS 27.0 Simulator; the signed app also builds for the connected iPhone 17 Pro running iOS 27 beta.

Mock checks were observed in the iPhone 17 Pro simulator or directly exercised by the named test through 25 July 2026. Live acceptance was observed on the same simulator on 23 July 2026.
